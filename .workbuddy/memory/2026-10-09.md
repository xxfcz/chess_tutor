## 修复 pnpm dev 下 HMR WebSocket 连接失败

- 现象：`WebSocket connection to 'ws://198.18.0.1:3050/_next/hmr?id=...' failed`
- 根因：Next.js 16.4.0 的 `blockCrossSiteDEV` 只放行 `localhost` / `**.localhost` / 启动 hostname，
  其余 origin 访问 `/_next/*`（含 HMR WebSocket）直接 403。
  `198.18.0.1` 是本机 Mihomo/Clash Meta TUN 虚拟网卡地址，Next dev 把它当成 "Network" 地址打印，
  用户点该地址打开页面时 origin 不匹配 → HMR 被拦截。
- 定位方式：curl 模拟 WS 握手对比 Origin（localhost 返回 101，198.18.0.1 被断开）。
- 修复：在 `next.config.ts` 顶层新增 `allowedDevOrigins: ['198.18.0.1', '192.168.*.*', '10.*.*.*', '172.16.*.*']`。
  改完 dev server 会自动重载配置，已验证 198.18.0.1 源握手返回 101。
- 备注：本机项目实际安装的是 next 16.4.0（package.json 写 ^16.0.7）。
- 备选方案：直接用 http://localhost:3050 或 http://127.0.0.1:3050 访问即可绕开。

## Gemini 模型名迁移：gemini-2.5-flash → gemini-3.8-flash

- 现象：`[GoogleGenerativeAI Error] ... [404] models/gemini-2.5-flash is no longer available to new users`
  （Google 已限制 2.5 仅对历史活跃用户开放，新 key 报 404）
- 修复：把散落在 8 处的硬编码模型名收敛到 `src/lib/gemini.ts` 的 `DEFAULT_GEMINI_MODEL`，
  支持 `NEXT_PUBLIC_GEMINI_MODEL` 环境变量覆盖（以后改名只改 .env，不用动代码）。
- 改动文件：
  - `src/lib/gemini.ts`：新增 `DEFAULT_GEMINI_MODEL` / `GEMINI_MODEL_FALLBACKS` / `isModelUnavailableError()`，
    `getGenAIModel` 默认值改用它；`getAvailableModels()` 列表更新为 3.8/3.5/3.5-lite/3.1-lite。
  - 调用方去掉第二参数改用默认值：`analysis/page.tsx`、`analysis/useAnalysisSession.ts`、
    `components/{Tutor,GameOverModal,GameAnalysisModal}.tsx`、`components/useTutorChat.ts`。
  - `api/v1/llm/chat/route.ts` 用 `modelName ?? DEFAULT_GEMINI_MODEL`。
  - `api/v1/llm/opening-explanation/route.ts` 从 `gemini-1.5-flash` 改为 `DEFAULT_GEMINI_MODEL`。
  - `lib/geminiErrorHandler.ts`：新增 `isModelError`，404/退役模型给出可操作提示（含 Google 建议的模型名）。
  - `chat/route.test.ts` 断言改用 `DEFAULT_GEMINI_MODEL`（jest.mock 需 `...jest.requireActual`）。
  - `.env.example` 补充 `NEXT_PUBLIC_GEMINI_MODEL` 说明。
- 验证：`npx tsc --noEmit` 本次改动无新增错误；相关 jest 用例 6/6 通过。
- 附带发现：服务端 `GEMINI_API_KEY` 未配置（`.env` 里没有），
  所以 `/api/v1/llm/opening-explanation` 永远走 `usedFallback: true` 兜底文案。
  客户端路径靠 localStorage 的 `gemini_api_key`，不受影响。

## 新增简体/繁体中文国际化
- 项目 i18n 是自研类型安全方案（`src/lib/i18n/translations.ts`）：`SupportedLanguage` 联合类型 + `Translations` 接口（单一真相源）+ 每种语言 const 对象 + `translations` 记录。
- 本次扩展：类型加 `'zh-CN' | 'zh-TW'`；新增 `zhCN`、`zhTW` 两个完整翻译对象；新增 `languageNames` 母语名映射（en/de/fr/it/pl/zh-CN/zh-TW）。

- 类型检查：`tsc --noEmit` 对我改动的文件无报错（项目本身存在一批无关的预存错误，如 useAnalysisSession、gameImport、若干测试文件）。
